# 个人工作台 业务设计文档（初版 v0.1）

> 文档性质：业务需求与设计，不含技术实现方案
> 日期：2026-08-12

---

## 一、项目概述

### 1.1 是什么

一个运行在个人电脑上的私人工作台，把**做事、规划、知识沉淀**三件事在一个地方打通，解决信息散落多个工具、缺乏全局视图的问题。

### 1.2 不是什么

- 不是生活管家（不碰记账、健康、人脉、购物等生活琐事）
- 不是团队协作工具（纯个人使用，无团队概念）
- 不是聚合面板（不只统一"看"，而是统一"管"）

### 1.3 核心痛点

**工具太散**--信息没有统一的家，也没有统一的全局视图。具体两层：

1. 没有统一的全局视图--看不到今天/本周到底该关注什么
2. 信息没有统一的归宿--任务在 A、笔记在 B、目标在 C，互相割裂、关联不上

### 1.4 路线选择：自建统一归宿

所有核心数据（任务、日程、笔记、目标等）都在本工作台内管理，数据集中、彻底打通。不聚合外部工具的数据源，而是让本系统成为所有个人工作/成长数据的唯一归宿。

这是最彻底的方案，代价是初期需要重建体系、迁移数据，但换来的是任何聚合方案都做不到的**数据天然打通**。

---

## 二、设计原则

| 原则 | 含义 |
|---|---|
| **自建统一归宿** | 数据天然打通，这是本系统一切价值的根基 |
| **统一内核 + 模块特化** | 内核统一提供标签、搜索、关联、仪表盘卡片等能力，任何模块（含未来新增）自动继承。新增模块只需定义：字段、与已有实体的关联、首页展示卡片 |
| **能用类型解决就不新增模块** | 控制复杂度膨胀的关键纪律。如"阅读管理"不是新模块，而是项目的"学习研究型"类型 |
| **不靠自觉靠流程** | 逾期任务不自动滚、收件箱定期清、复盘清债--靠机制驱动而非意志力 |
| **每个机制对准一个痛点** | 不堆功能，每个设计决策都能追溯到它解决的具体问题 |

### 可扩展性（第一原则）

系统必须支持后续随时加入新功能，且不推翻重做。三条落地要求：

1. **仪表盘卡片式可组合**--首页由若干卡片拼成，能加、能删、能换顺序，新模块有地方待
2. **统一内核能力自动继承**--新模块的内容天然可被搜索、可打标签、可关联、可进复盘
3. **优先用"类型"扩展而非新模块**--想管书/课程/论文，给项目加类型，不新建模块

## 三、模块总览

系统共 12 个模块，按性质分三类：

### 数据源头（有独立内容，需"新建"入口）
- ① 任务管理
- ② 日程日历
- ③ 项目管理
- ⑤ 目标管理
- ⑥ 习惯打卡
- ⑨ 收件箱 / ⑩ 知识库（一条流水线的两端）

### 聚合视图（不产生新数据，换个角度看已有数据）
- ⑦ 周期计划
- ⑱ 仪表盘首页
- ⑲ 全局搜索

### 附着属性（依附在别的实体上，不能独立存在）
- ⑳ 标签体系

### 混合体
- ⑧ 复盘回顾（消费所有数据生成回顾，同时产出一篇文档）

> 说明：原"阅读管理"已泛化为项目的"学习研究型"类型，不再作为独立模块。原"专注计时"已砍掉。

### 模块关系图

## 四、各模块详细设计

---

### ① 任务管理

**定位**：每天用得最多的模块，执行层的核心。

#### 4.1.1 核心区分：截止日期 ≠ 计划日期

| | 截止日期 Due | 计划日期 Plan |
|---|---|---|
| 含义 | 最晚什么时候必须做完 | 我打算哪天做 |
| 谁决定 | 外部约束 | 你自己 |
| 会不会变 | 基本不变 | 经常调 |
| 例子 | 报税截止 4/30 | 我打算 4/12 弄 |

只有一个日期字段的工具会迫使你在"记录约束"和"安排行动"之间二选一。双日期分开后：今日清单只看计划日期，死线提醒只看截止日期。一个任务可以"截止在月底，但我计划今天做"。

#### 4.1.2 字段

- **必要**：标题、状态、计划日期、所属项目（可空）
- **可选**：截止日期、重点标记、标签、备注、清单项
- **刻意不加**：预估时长（估不准且不看）、指派人（个人场景不需要）

#### 4.1.3 层级：三层封顶

```
③项目  "搭建个人工作台"
  └─ ①任务  "设计首页布局"
       └─ 清单项  ☐ 画草图  ☐ 定卡片  ☐ 确认交互
```

- 清单项是纯勾选，没有自己的日期、不能挂项目、不进今日清单
- **不做无限层级子任务**。需要更多层次时，升级成项目，而不是往下套

#### 4.1.4 状态：三态

**未开始 / 已完成 / 已放弃**

- 不设"进行中"：对个人任务几乎无信息量，只增加点击
- "已放弃"独立保留：不用删除代替，复盘时"这季度放弃了 12 个任务"有价值

#### 4.1.5 逾期任务：不自动滚动

计划日期到了没做完，**不自动滚到今天**（否则今日清单变成不断累积的坟场）。过期任务单独归到「待重新安排」栏，必须给一个新决定：

- 推到今天
- 挑个日期
- 去掉计划日期退回待办池
- 放弃

每个按钮一次点击，不麻烦，但强迫正视。今日清单永远是你亲自认领过的。

#### 4.1.6 重复任务 vs 习惯

| | 习惯⑥ | 重复任务 |
|---|---|---|
| 关心什么 | 做没做、连续多少天 | 这一次做完没有 |
| 漏掉会怎样 | 断签，不留待办 | 变成逾期，必须补 |
| 例子 | 阅读、运动、早起 | 交房租、体检、月度报表 |

**判断规则：漏掉一次要不要补？** 要补的是重复任务，不用补的是习惯。两者各管各的：习惯只生成打卡格子，重复任务每次生成真实任务实例，会逾期、会进「待重新安排」。

#### 4.1.7 优先级：不做分档

不设三档五档优先级（实际结局通常是所有东西都标成高）。只保留一个二元的**「重点」标记**，用于当天排序。

#### 4.1.8 视图

- **今日**：计划日期=今天 ＋「待重新安排」栏 ＋ 今日截止提醒
- **待办池**：还没给计划日期的任务，每周安排的原料
- **按项目**：进某个项目看它下面的所有任务
- **日历**：见②日程

#### 4.1.9 待办池 -> 今日的路径

每周从待办池挑一次，放进⑦周期计划，落到具体周几。不做每天临时挑。计划动作有固定时机（周计划），不靠临时起意。

---

### ② 日程日历

**定位**：时间维度的视图，与任务是一体两面。

#### 4.2.1 两类内容并存

| 类型 | 含义 | 例子 | 需要完成吗 |
|---|---|---|---|
| 任务时间块 | 我要做的事 | 14:00 设计首页布局 | 是（来自任务①） |
| 独立事件 | 我被占用的时间 | 10:00 公司周会 | 否（过去了就过去） |

**允许独立事件**--不是所有日程都该先变成任务。开会不是"待办"，强制它变任务会污染待办清单和完成率。

#### 4.2.2 三层视觉结构

```
   周三 4/15
 ┌──────────────────────────┐
 │ 🔴 截止：报税                    │ ← 截止标记（只提示，不占时间）
 │ ☐ 整理收件箱                     │ ← 全天区（计划今天但没排时间）
 ├──────────────────────────┤
 │ 10:00 ┃ ▢ 公司周会              │ ← 独立事件（被占用）
 │ 14:00 ┃ ▨ 设计首页布局           │ ← 任务时间块（我要做）
 └──────────────────────────┘
```

- **截止标记**：只提醒，不占时间
- **全天区**：今天要做但没排具体时间的任务
- **时间轴**：真正占用时段的东西

#### 4.2.3 与任务的联动

给任务加具体时间 -> 出现在时间轴；在日历上拖动 -> 改计划时间。**同一个东西，两个视角**，不是两份数据。

### ③ 项目管理

**定位**：组织层，把多个任务聚合成有产出的工作块。

#### 4.3.1 目标 vs 项目的判断规则

**能不能拆成任务、然后"做完"？** 能 -> 项目。只靠做一堆事逐渐逼近、没有"完成"那一刻 -> 目标。

| 说法 | 是什么 | 为什么 |
|---|---|---|
| 成为更好的前端工程师 | 都不是 | 不可衡量，需先翻译成可衡量目标 |
| 今年读完 20 本书 | 目标 | 可衡量，但没有"做完"那一下 |
| 读完《设计心理学》 | 项目（学习研究型） | 有终点，可拆任务 |
| Q4 上线工作台 V1 | 项目（交付型） | 有交付物 |
| 今年持续输出技术文章 | 目标 | 是方向，靠一篇篇逼近 |

#### 4.3.2 两种类型

```
③项目
 ├─ 交付型     "搭建个人工作台"
 │    进度 = 任务完成度        产出 = 成品
 │
 └─ 学习研究型  "研究React并发渲染" / "读完《设计心理学》"
      进度 = 素材消化 + 子主题覆盖   产出 = ⑩知识库条目
      └─ 素材清单：书 / 文章 / 视频 / 文档
           （书这种素材才有作者、页数、阅读进度等字段）
```

"读一本书"和"研究一项技术"形状一样：持续投入、有进度、有产出。书只是其中一种素材。书特有的属性（作者、页数、阅读进度）下沉到"素材"层。

> 素材是挂在具体学习项目下的清单，不是漫无目的的收藏池（与已砍掉的"收藏/稍后读"不冲突）。

#### 4.3.3 状态：五态

**未开始 / 进行中 / 已完成 / 已归档 / 已放弃**

- 项目必须有"进行中"（和任务不同）：项目横跨数周、同时多个，"哪些在推进、哪些搁着"是每天都要判断的
- "已归档"≠"已完成"：归档是不做了但不算放弃（无限期搁置），能从视野消失又不丢历史

#### 4.3.4 进度

默认由下属任务完成度自动算，允许手动覆盖（有些项目任务数不代表进度）。

#### 4.3.5 聚焦机制（防项目失控）

- 项目分「**当前聚焦**」和「**其他**」两栏
- 聚焦超过上限（建议 3～5 个）时给提示，不硬性阻止
- ⑦周期计划每周只从「当前聚焦」里挑任务--没聚焦的项目本周不该有产出
- 没聚焦的项目自动沉底，不占注意力

### ⑤ 目标管理

**定位**：方向层，给项目和任务提供"为什么"。

#### 4.5.1 层级不强制

目标 -> 项目 -> 任务三层**都能独立存在，关联是可选的**：

```
⑤目标 ──▶ ③项目 ──▶ ①任务     完整链路
⑤目标 ──────▶ ①任务     目标直接挂任务（跳过项目）
          ③项目 ──▶ ①任务     项目独立存在（无上级目标）
                ①任务     光杆任务（大量日常就是这样）
```

关联是"你想建立时才建立"的增值信息，不是录入前置条件。强制三层会逼你编内容。

#### 4.5.2 字段

标题、周期、进度算法、状态、标签、备注

#### 4.5.3 进度算法

| 类型 | 适用 | 例子 |
|---|---|---|
| **计数型** | 可量化的累积 | "读完 20 本书" -> 12/20 |
| **汇总型** | 靠下属项目推进 | 进度 = 下属项目完成度平均 |

- 计数型数值：允许手动填，也允许挂来源自动加（学习型项目完成则书数 +1；习惯打卡数直接喂给"今年运动 150 次"）
- 不强制自动化--填不上就手动改，别为自动化把录入搞复杂

#### 4.5.4 周期

- **季度 + 年度**两级
- 加一档**「长期」**：容纳跨年方向（"持续输出技术文章""长期健身"）。长期目标可以不设终点，但**必须设有当期的计数目标**，否则容易变许愿池
- **不做 OKR 的 KR 拆解**--个人场景形式成本远大于收益，"目标 + 进度数字 + 下挂项目"已足够

### ⑥ 习惯打卡

**定位**：例行层，管理重复行为，与重复任务严格区分。

#### 4.6.1 二元打卡

**做了 / 没做**，一次点击完成，无确认。不做计量（"今天喝了 8 杯水中的几杯"是负担）。如以后需要计量，按可扩展原则加可选字段，不影响默认体验。

#### 4.6.2 两种频率，两种显示

| 频率 | 显示 | 漏一次 |
|---|---|---|
| 每天 | 🔥 连续 12 天 | 断签，连续归零 |
| 每周 N 次 | 本周 2/3 | 不算断，本周内凑够 N 次即可 |

每周 N 次型没有"连续"概念。

#### 4.6.3 漏掉不补、不宽限、不留债

- **不补卡**：漏了就是漏了，连续归零。保留"最长连续 N 天"作为历史最好成绩
- **不宽限**：不做冻结道具，习惯的力量来自"漏了真会断"
- **不留债**：不生成待办、不逾期、不进「待重新安排」

#### 4.6.4 与目标的联动

习惯打卡数可直接喂给计数型目标（自建体系才有的打通）：

```
⑥习惯"运动" 打卡一次
      └──▶ ⑤目标"今年运动150次"  ▓▓▓░░ 86/150 自动 +1
```

关联可选--很多习惯（早起、冥想）无对应目标，纯打卡。

#### 4.6.5 暂停与归档

- **暂停**：出差/生病临时停掉，暂停期间不断签、不提醒，设结束日期自动恢复
- **归档**：习惯养成或放弃，归档移出视野，历史记录不丢

#### 4.6.6 视图

- **首页**：当日打卡按钮 + 连续天数/本周次数
- **详情**：打卡热力图（GitHub 贡献图样式）
- **历史**：归⑧复盘自动摘要

### ⑦ 周期计划

**定位**：连接"待办池"和"今日聚焦"的中间环节。

#### 4.7.1 本质：一个"承诺"动作

待办池是仓库，周期计划是契约。一旦进入周期计划，任务带上"本周必须有个交代"的约束。

#### 4.7.2 两个层级

| | 周计划 | 月计划 |
|---|---|---|
| 频率 | 每周一次（必须） | 每月一次（可选） |
| 管什么 | 任务 | 项目和目标 |
| 核心动作 | 从待办池挑任务，落到周几 | 调整聚焦项目，校准目标 |

#### 4.7.3 周计划

```
┌─ 本周 4/15 - 4/21 ──────────────────────┐
│ 📌 聚焦项目（3/5）                        │
│   ▸ 搭建个人工作台     ▓▓▓░░ 3/8         │
│   ▸ 读《设计心理学》   ▓▓░░░ 40%         │
│   ▸ React并发渲染研究  ▓░░░░ 2/6         │
│                                         │
│ 本周承诺（5）           待办池（23）       │
│ ┌──────────────┐  <-拖拽->  ┌──────────────┐│
│ │☐ 设计首页布局  周三          │ │☐ 联系供应商     ││
│ │☐ 整理收件箱    周一          │ │☐ 写技术文章     ││
│ │☐ 读第1-3章     周二          │ │☐ 重构登录模块   ││
│ │☐ 并发渲染笔记  周五          │ │☐ ...           ││
│ │☐ 公司报表      周四          │ │                ││
│ └──────────────┘             └──────────────┘│
│ 进度 ▓▓▓░░ 3/5              [开始周复盘]      │
└─────────────────────────────────────────┘
```

- 核心是双栏拖拽：拖到左边即承诺，必须指定计划日期（周几），否则不算承诺成功
- **只到"周几"**，精确时间留到当天早上排（周计划是"承诺做什么"，不是"安排每分钟"）

#### 4.7.4 月计划

```
┌─ 4月计划 ───────────────────────────────┐
│ 目标回顾                                 │
│   读完20本书     ▓▓▓░░ 12/20  正常       │
│   技术文章       ▓░░░░ 4/12   落后 ⚠     │
│                                         │
│ 聚焦项目调整                             │
│   当前聚焦（4）          备选池（6）       │
│   ▸ 工作台    <-->       ▸ 博客重构       │
│   ▸ 设计心理学 <-->      ▸ 算法复习       │
│                                         │
│ 本月承诺（从聚焦项目推导，不重复录入）        │
│   ▸ 工作台：完成首页+任务模块              │
│   ▸ 设计心理学：读完前6章                 │
└─────────────────────────────────────────┘
```

- 关键动作是**调整聚焦项目**（移出停滞的、拉进备选的）
- "本月承诺"不是新录数据，是从聚焦项目进度推导的视图

#### 4.7.5 关键规则

1. **周计划只管"挑哪些 + 放哪天"**，不管"怎么做"（那是任务详情和今日聚焦的事）
2. **未完成的周承诺不自动滚到下周**。周日复盘时逐条决定：完成/推到下周/退回待办池/放弃
3. **月计划可跳过，周计划不可**。到周一还没做周计划，首页提示"本周还没安排"
4. 计划日期联动：周计划指定"周三" -> 周三出现在今日聚焦 -> 没做完走「待重新安排」

```
待办池 --周计划挑--> 本周承诺 --指定日期--> 今日聚焦 --做完--> ✓
                                              |
                                         没做完 ↓
                                       待重新安排 --显式决定-->
```

### ⑧ 复盘回顾

**定位**：系统的节拍器，把散落各处的卫生工作收拢到固定流程。

#### 4.8.1 核心理念

**复盘不是写文章，是"系统摆数据 + 引导做决定"**。复盘页面打开应该是满的（数据已预填、待办已列出），不是空的。

#### 4.8.2 周复盘：五步固定流程

```
周复盘
 ├─ ① 看摘要    自动摘要 + 异常提示（不用写）
 │
 ├─ ② 清欠债    处理本周未完成承诺
 │              未完成的不许滑到下周，逐条决定：
 │              完成 / 推到下周 / 退回待办池 / 放弃
 │
 ├─ ③ 清收件箱  ⑨收件箱三向分流（转任务/升级知识/删除），清零
 │
 ├─ ④ 回答几个问题  引导问题，可简短
 │
 └─ ⑤ 做下周计划    接⑦周计划（承诺+排到周几）
```

前三步是"清债"，后两步是"向前看"。做完五步，本周卫生工作清零，下周也有了承诺。

#### 4.8.3 自动摘要：不是数字罗列，是异常发现

```
┌─ 本周摘要 4/15 - 4/21 ─────────────────────┐
│ 任务   完成 3/5    上周 5/5   ↓ 下降       │
│ 习惯   阅读 7/7 ✓   运动 2/3 ⚠ 差一次      │
│ 目标   读完20本书 12/20  正常              │
│        技术文章  4/12   落后 ⚠ 本周0产出    │
│ 收件箱 待整理 8 条                         │
│ 逾期   待重新安排 2 条                     │
│                                           │
│ 💡 本周技术文章产出为0，目标已落后，下周需关注 │
└──────────────────────────────────┘
```

数字 + 上周对比 + 异常标记 + 一句话洞察。洞察把"4/12 落后"和"本周 0 产出"连起来，替你发现可能忽略的关联。

#### 4.8.4 引导问题：少而固定

- 本周什么做得好？（留住有效动作）
- 什么没做完，为什么？（诚实归因，不是自我批判）
- 下周最重要的三件事？（逼你排优先级，而不是列 20 件）

固定问题比自由发挥好--好处是积累，几十周后能横向对比模式。模板允许自定义，默认就这三问。

#### 4.8.5 复盘文档的归处

进⑩知识库，自动打「复盘」标签，自动关联当期目标：

```
⑩知识库
 ├─ 知识条目（技术总结、读书笔记…）
 └─ 复盘记录
      ├─ 2024-W15 周复盘  [复盘] [关联:工作台V1]
      ├─ 2024-W14 周复盘  [复盘]
      └─ 2024-04 月复盘   [复盘] [关联:技术文章]
```

#### 4.8.6 日复盘与月复盘

- **日复盘不做独立流程**。首页"今日小结（可不写）"就是全部--一句话甚至一个词，不强制
- **月复盘**是周复盘放大版，多一步"目标进度校准"（季度目标过半了吗？提速还是放弃？）

| | 周复盘 | 月复盘 |
|---|---|---|
| 清什么 | 任务欠债、收件箱 | 同左 + 目标进度校准 |
| 想什么 | 这周做得怎样 | 方向对不对、项目该不该调整 |
| 接什么 | 周计划 | 月计划（调聚焦项目） |

#### 4.8.7 不绑日子

- 复盘按**周期窗口**触发，不绑固定日子。自然周结束后窗口打开，随时可做
- 系统温和提示"上周复盘还没做"，能忽略、能跳过、不催命
- **债不消失**：未完成承诺和收件箱不会因你不复盘就蒸发，它们挂在首页直到你处理
- **复盘与计划解耦**：可以先做计划再补复盘，顺序自定，建议复盘在前
- **可跳过但跳过有记录**：月复盘显示"第 N 周未复盘"；连续跳过 2 周首页提示升级

### ⑨ 收件箱 → ⑩ 知识库（记事流水线）

**定位**：没有独立的"笔记模块"和"知识库模块"，而是一条"收件箱 -> 知识库"的内容流水线。

#### 4.9.1 设计逻辑

| 方案 | 描述 | 问题 |
|---|---|---|
| ~~两个独立模块~~ | 笔记随手记，知识库认真写 | "手动搬运"几乎不发生，知识库长期空着，笔记堆成山 |
| ✅ 一套内容两态 | 所有文字内容是同一种东西，处于不同成熟度 | 依赖"整理"动作，需机制保障 |

选择**一套内容、两种状态**，但补上整理的保障机制。

#### 4.9.2 两态结构

- **收件箱 Inbox**：刚捕捉，未处理
- **知识库 Knowledge**：已加工，长期留存

不要中间态（"整理中"之类会变成第二个垃圾堆）。

#### 4.9.3 记录零门槛

首页快速记录框或全局快捷键，随手输入回车即存，不问标题不问分类，直接进收件箱。

#### 4.9.4 三向分流（整理动作）

收件箱里混着三类东西，整理时三向分流：

| 类型 | 例子 | 该去哪 |
|---|---|---|
| 待办 | "记得给张三回邮件" | 转成任务① |
| 知识/想法 | "React 18 并发渲染的原理是…" | 升级进知识库⑩ |
| 垃圾 | 当时有用，现在没意义 | 删掉 |

每条三个按钮：「转任务」「升级为知识」「删除」，处理完清零。

#### 4.9.5 升级为知识的三条标准

- 有明确标题
- 归属至少一个主题
- 内容自洽（未来的你看得懂）

#### 4.9.6 整理焊进复盘流程

不指望自觉。**周复盘第③步固定处理收件箱**，处理完清零。整理靠流程驱动，不靠意志力。

### ⑩ 知识库内部组织

**定位**：沉淀层的结构化存储，解决"存进去找不找得到、会不会变孤岛"。

#### 4.10.1 三个痛点与三层机制

| 痛点 | 机制 |
|---|---|
| 不知道往哪放（分类障碍） | 主题 |
| 存了找不到 | 标签 + 全局搜索 |
| 知识孤立（存了就忘） | 双向链接 + 实体关联 |

#### 4.10.2 第一层：主题（骨架）

```
主题（5～8个，手动维护，稳定）
 ├─ 前端工程
 ├─ 产品设计
 ├─ 读书笔记
 ├─ 职业思考
 └─ 工具技巧
```

- **少量、稳定**：5～8 个，不轻易增减，是浏览入口
- **每条内容必选一个主题**（升级进知识库的硬要求）
- **扁平，不做层级**（树状层级是负担）

#### 4.10.3 第二层：标签（细分）

- 自由、扁平、多标签、可选
- 不做标签层级（那是变相目录树）
- 组织靠主题，检索靠标签 + 搜索
- 主题是"它在哪个书架"，标签是"它还和哪些东西相关"

#### 4.10.4 第三层：双向链接（关联网络）

```
《React并发渲染原理》
  正文：这依赖于 [[时间分片]] 和 [[调度器]] 的配合

打开《时间分片》时，底部自动显示：
  反向链接：
  ← 《React并发渲染原理》
  ← 《为什么React需要并发》
```

- `[[条目名]]` 语法，写时随手链接，自动建立双向关联
- 反向链接 = 天然的相关推荐，让沉睡的知识被重新看到
- 也关联其他实体（项目、目标、任务）
- **可选、不强制**：初期条目少时链接意义不大，需积累

#### 4.10.5 为什么不选目录树

| 问题 | 后果 |
|---|---|
| 一条内容只能放一个文件夹 | "React 性能优化"放前端还是性能？纠结 |
| 层级越深越看不见 | 深层内容永远不被翻到 |
| 改分类要搬整棵子树 | 维护成本高 |

扁平主题 + 多标签 + 双链，用**多重归属**替代**单一位置**。

#### 4.10.6 浏览与检索（四种方式）

- **按主题浏览**：系统性看某个领域
- **全局搜索⑲**：知道关键词时，跨标题+正文+标签
- **按标签筛选**：看某类切片
- **顺链接跳**：从一条知识跳到相关的

#### 4.10.7 知识条目来源

| 来源 | 怎么进 |
|---|---|
| 收件箱升级 | 三向分流时「升级为知识」，给标题+主题 |
| 直接新建 | 知识库新建入口（日常更推荐走收件箱） |
| 复盘文档 | 自动生成，带「复盘」标签，自动关联当期目标 |
| 读书笔记 | 学习研究型项目③下素材读完，笔记可升级进库 |

### ⑱ 仪表盘首页

**定位**：全局入口，解决"一打开就知道现在该做什么"。

#### 4.18.1 设计目标

**打开它，3 秒内知道现在该做什么，且不用再去任何模块巡逻。**

推论：
1. 卡片按"是否需要现在行动"排序，不按模块归类
2. 不需要行动的东西不占位置（无逾期时「待重新安排」整张卡消失）

#### 4.18.2 性质澄清

仪表盘不拥有任何数据，但可以是其他模块的**写入入口**（快速记录写进收件箱，打卡写进习惯）。它自己永远不需要"新建仪表盘条目"。

#### 4.18.3 默认布局

```
┌─ 周三 4/15 ──────────────────── [＋快速记录]  ⚙ ─┐

 ┌─ 今日 ────────────────────────── [＋] ─┐
 │ 🔴 截止｜报税                              │
 │ ──────────────────────────            │
 │ ⭐ 14:00 ▨ 设计首页布局  └ 搭建个人工作台    │
 │    10:00 ▢ 公司周会        （独立事件）      │
 │    全天  ☐ 整理收件箱                     │
 │    全天  ☐ 写季度总结                     │
 │         ☑ 回复张三邮件                   │
 │ ──────────────────────────            │
 │ ⚠ 待重新安排 (2) >                       │
 └────────────────────────────────┘

 ┌─ 习惯 ────────────────┐ ┌─ 目标进度 ────────┐
 │ ● 阅读30分钟    🔥 12天 │ │ 读完20本书  ▓▓▓░ 12 │
 │ ○ 运动(每周3)   本周2/3 │ │ 技术文章    ▓░░░  4 │
 └────────────────────────┘ └────────────────────┘

 ┌─ 收件箱 8 条待整理  ｜  周复盘可以做了 -> [开始] ┐
 └────────────────────────────────┘

 今日小结：_________________________ (可不写)
```

四个区块从上到下：**行动 -> 欠债 -> 例行 -> 状态**。

> 注：原设计的"站会卡"已移除（本工作台聚焦个人场景，非公司团队协作）。

#### 4.18.4 逐卡交互

**今日卡**（合并了原"今日聚焦"与"今日程"）
- 勾选即完成，就地操作不跳转
- ⭐重点标记置顶，穿透时间顺序
- 任务下方灰字显示所属项目
- 时间轴：▨ 任务时间块（我要做）、▢ 独立事件（被占用），一眼可分
- 只显示计划日期=今天的任务，逾期的不混进来（在底部折叠栏）
- 逾期以一行「待重新安排 (N) >」折叠挂在卡底，不污染主列表

**习惯卡**
- 一次点击打卡，无确认
- 每天型显示 🔥连续天数，每周 N 次型显示"本周 2/3"

**目标进度卡**
- 只有数字和进度条，不放图表
- 长期档目标显示当期计数

**底部条**
- 收件箱堆积超阈值（如 5 条）才出现
- 周复盘入口只在周期窗口打开后出现
- 两者都是"系统提醒你还欠着卫生工作"

#### 4.18.5 三个刻意不做

- **不显示"未来几天"**--首页只管今天，看未来去日历，安排未来去周计划
- **不做完成率统计和趋势**--卡片上的 1/3 是当天口径，历史归复盘
- **不做自由拖拽布局**--卡片能换顺序、能隐藏、能调宽窄档（半宽/全宽），但走固定栅格

#### 4.18.6 空状态

| 情况 | 显示 |
|---|---|
| 今天没排任务 | "今天还没安排 -> [从待办池挑]"，直接给出路 |
| 全部完成了 | 显示完成态，**不推荐新任务**--做完了该收工 |
| 无逾期/收件箱空/复盘未到点 | 对应卡片整张不渲染 |
| 刚开始用 | 只显示快速记录 + 一句引导，不展示空壳卡 |

#### 4.18.7 卡片式可组合

首页由若干卡片拼成，能加、能删、能换顺序。这是可扩展第一原则的落地--新模块进来有地方待，你也能随时调整"一打开看到什么"。

### ⑲ 全局搜索

**定位**：解决"工具太散"的终极武器，自建路线的核心红利。

#### 4.19.1 一个搜索框搜所有东西

```
⌘K 唤起
┌─────────────────────────────────────┐
│ 🔍 性能                       [⌘K]  │
├─────────────────────────────────────┤
│ 任务 (3)                              │
│   ☐ 优化首屏加载性能        └工作台   │
│   ☐ React列表性能调研       └React研究│
│ 知识 (5)                              │
│   📄 React并发渲染原理      [前端工程] │
│   📄 虚拟DOMdiff算法        [前端工程] │
│ 项目 (1)                              │
│   ▸ 首屏性能优化                       │
│ 目标 (1)                              │
│   🎯 今年输出12篇技术文章              │
│ 标签 (1)                              │
│   #性能  共12条相关                    │
└─────────────────────────────────────┘
```

#### 4.19.2 设计要点

- **范围**：所有实体--任务、项目、目标、日程、习惯、知识条目、收件箱、复盘文档、标签
- **字段**：标题、正文、备注、标签名
- **入口**：全局快捷键 ⌘K，任何页面随时唤起
- **结果默认按类型分组**，可切换混合排序（按相关度）
- **过滤语法**：`性能 type:任务`、`react tag:前端`、`未完成`。不强制学，熟练了能精准定位
- **结果上直接操作**：搜到的任务能直接勾选完成，搜到的知识条目能直接打开

### ⑳ 标签体系

**定位**：唯一能跨所有模块横向切片的机制。

#### 4.20.1 与主题、项目的区分

| | 范围 | 作用 | 强制 |
|---|---|---|---|
| 主题 | 仅知识库 | 知识的粗骨架 | 强制选一个 |
| 项目 | 做事模块 | 组织任务、有进度状态 | 独立实体 |
| **标签** | **全局所有实体** | **横向标记、跨类型串联** | **可选** |

#### 4.20.2 杀手场景：跨类型切片

```
#性能
 ├─ 🎯 目标：今年掌握前端性能优化体系
 ├─ ▸ 项目：首屏性能优化
 ├─ ☐ 任务：优化首屏加载
 ├─ ☐ 任务：React列表调研
 ├─ 📄 知识：React并发渲染原理
 ├─ 📄 知识：虚拟DOM diff算法
 └─ 📄 知识：浏览器渲染流水线
```

这个视图任何单一模块都给不了。标签告诉你"在某条线上，我布了哪些局、做了哪些事、沉淀了什么"。

#### 4.20.3 设计要点

- **全局统一标签池**：一个"性能"标签同时贴在目标、项目、任务、知识上，不是每模块各搞一套
- **扁平，不做层级**
- **任何实体可打标签，可选**，不阻塞录入
- **防失控三招**：
  - 自动补全：输入时提示已有标签，避免"React""react""React.js"并存
  - 合并同义：一键合并，所有引用自动更新
  - 清理废弃：长期没用的归档，不占视野但不丢历史

#### 4.20.4 与搜索的关系

搜索是**点**（找具体的东西），标签是**线**（看某一类的切片）。互补：

- 搜索结果里能看到标签，点标签切到切片视图
- 标签切片里能再搜（在"性能"线里搜"React"）
- `tag:性能` 是两者的交汇--用搜索调取标签切片

## 五、贯穿全局的机制汇总

### 5.1 "不靠自觉靠流程"的四处体现

| 机制 | 在哪执行 | 规则 |
|---|---|---|
| 逾期任务不自动滚 | 今日卡「待重新安排」 | 必须显式决定（今天/改期/退回池/放弃） |
| 收件箱定期清零 | 周复盘第③步 | 三向分流，清零 |
| 未完成周承诺不自动滚 | 周复盘第②步 | 逐条决定（完成/推下周/退回池/放弃） |
| 习惯漏掉不补 | 习惯模块 | 断签归零，不生成待办 |

### 5.2 数据打通的关联关系

| 来源 | 关联到 | 作用 |
|---|---|---|
| 任务 | 项目（可选） | 知道任务在为什么服务 |
| 任务 | 日程（排时间） | 同一东西两个视角 |
| 项目 | 目标（可选） | 自上而下拆解，自下而上汇总 |
| 习惯 | 目标（可选） | 打卡数自动喂目标进度 |
| 知识条目 | 任意实体 | 知识挂在工作流的节点上 |
| 知识条目 | 知识条目（双链） | 关联网络 |
| 标签 | 所有实体 | 横向跨类型串联 |
| 复盘文档 | 当期目标 | 成长轨迹有迹可循 |

### 5.3 可扩展机制汇总

| 内核能力 | 新模块自动获得 |
|---|---|
| 标签 | 新内容天然可打标签 |
| 全局搜索 | 新内容天然可被搜到 |
| 任意关联 | 新实体可和已有实体互挂 |
| 仪表盘卡片 | 新模块可往首页加卡片 |
| 复盘接入 | 新模块数据可进复盘摘要 |
| 自定义字段 | 不改结构就能加属性 |

## 六、待定与后续

### 6.1 本版已确认的决策

- [x] 路线：自建统一归宿
- [x] 场景：工作 + 生活 + 知识 + 规划，砍掉生活类
- [x] 阅读管理泛化为项目类型，不独立
- [x] 砍掉专注计时

- [x] 任务的截止/计划双日期
- [x] 逾期不自动滚动
- [x] 优先级不分档，只留二元「重点」
- [x] 每周从待办池挑一次
- [x] 目标层级不强制
- [x] 习惯断签归零
- [x] 周计划只到"周几"
