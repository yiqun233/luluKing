# R1-04：周计划与复盘联动技术设计（v0.1）

> 状态：已完成
>
> 所属阶段：R1 核心工作流闭环
> 日期：2026-08-24

---

## 一、目标

让周计划中的任务成为可追踪承诺，并在同周期复盘时给出完成统计和未完成去向决策。

## 二、数据契约

新增 `plan_tasks` 承诺表，字段包括：

- `plan_id`、`task_id`：计划与任务关联，组合唯一。
- `resolution`：空值表示待决；其余为 `completed`、`rolled_over`、`backlog`、`abandoned`。
- `resolved_at`：决策时间。

该表必须进入 JSON 备份、前端导入校验和 Rust 原子恢复；旧格式备份缺少该表时按空数组兼容。

## 三、行为

- 周计划只从待办池选择任务，保存后形成承诺关系。
- 周复盘汇总承诺总数、已完成数与待决数，并继续保留逾期、收件箱和习惯统计。
- 待决承诺必须选择：完成、推到下期、回到待办池、放弃。
- 推到下期时安排到下周第一天；若下周计划已存在，则自动加入其承诺列表。

## 四、完成条件

- `plan_tasks` 在迁移、备份和恢复后关系保持一致。
- 周计划可选择、移除承诺任务。
- 周复盘可完成全部待决承诺的去向决策。
- 自动化测试覆盖关系保存、恢复、统计和四种决策。

## 五、实施记录（2026-08-25）

- 新增 `005_plan_commitments.sql`：建立 `plan_tasks`、索引，以及任务完成/重新打开时同步承诺状态的触发器。

- `plan_tasks` 已进入备份、前端导入校验和 Rust 原子恢复；旧备份缺少该字段时按空数组兼容。
