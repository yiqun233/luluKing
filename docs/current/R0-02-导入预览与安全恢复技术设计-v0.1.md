# R0-02：导入预览与安全恢复技术设计（v0.1）

> 状态：已完成（附件备份除外）  
> 所属阶段：R0 可靠单机版与发布基线  
> 日期：2026-08-13

---

## 一、目标与边界

本任务将现有 JSON 备份从“可创建”升级为“可选择、可预览、可安全覆盖恢复”。恢复始终是全量恢复，不支持逐表或部分合并。

本任务包含：

- 从用户选择的 JSON 文件读取内容，不直接给前端外部文件系统权限。
- 恢复前展示备份版本、导出时间、数据数量和附件策略。
- 在前端和 Rust 端各做一次格式、字段、枚举、主键和关联校验。
- 恢复前自动创建当前数据的安全备份。
- Rust 端使用单个 SQLite 事务清空并写入业务表；任一步失败即回滚。
- 成功后重新加载应用数据。

本任务不包含：

- 跨格式版本转换、选择性恢复、数据合并和冲突处理。
- 附件文件及其数据库记录的导入恢复。
- 跳过预览、确认或自动安全备份的快捷恢复路径。

---

## 二、恢复流程

```text
选择 JSON 文件
  → 前端只读解析与校验
  → 展示预览及风险说明
  → 用户明确确认
  → 创建当前数据的自动安全备份
  → Rust 再次校验同一份 JSON
  → SQLite 单事务删除并按依赖顺序写入
  → 提交事务
  → 清空前端缓存并重新加载应用
```

只要前端校验、自动备份、Rust 校验或事务中的任何一个步骤失败，恢复不会开始或事务会回滚；当前业务数据保持不变。自动安全备份会保留在应用数据目录，可作为人工恢复来源。

## 三、校验规则

恢复仅接受：

- `format` 为 `luluKing-backup`。
- `formatVersion` 为当前支持的 `1`。
- `databaseVersion` 为正整数且不高于当前数据库版本。
- `attachmentPolicy` 为 `excluded`。
- 所有 15 张业务表均为数组，且记录包含预期列。
- 所有字段为字符串、数字或空值；不接受嵌套对象、数组和布尔值。
- 主键唯一，所有外键和多态标签引用均有对应实体。
- 状态类字段符合已定义枚举；日期字段符合 `YYYY-MM-DD`。

前端校验负责即时反馈；Rust 校验是实际写库前的安全边界，不能被绕过。

## 四、附件策略

当前备份格式明确不包含附件和 `files` 表。为避免恢复过程中把已有附件记录变为无关联数据，恢复命令会先检查当前数据库：只要存在任何附件记录，即拒绝恢复，并提示用户当前版本不支持含附件数据的安全恢复。

后续启用附件备份后，需要升级备份格式版本，并把二进制文件与 `files` 记录以数据包形式纳入同一恢复事务的外围流程。

## 五、事务与写入顺序

事务开始前完成全部 JSON 校验。事务内按以下顺序删除和写入：

1. 删除：标签关联、笔记链接、习惯记录、任务清单、日程、素材、任务、笔记、习惯、项目、标签、主题、目标、复盘、计划。
2. 写入：目标、主题、标签、项目、习惯、笔记、复盘、计划、任务、素材、任务清单、日程、习惯记录、笔记链接、标签关联。

SQLite 外键检查在恢复连接中开启。写入使用预定义的表名和列名、参数绑定，不把备份内容拼接进 SQL。

## 六、验收标准

- 有效备份可显示预览，并在确认后恢复全部业务数据。
- 损坏 JSON、未知格式、未来版本、重复主键、枚举错误或孤儿引用均在写库前被拒绝。
- 事务内任意写入失败不会留下半恢复数据。
- 恢复前自动备份创建失败时，不允许开始恢复。
- 当前数据库包含附件记录时，恢复被拒绝且不修改数据。
- 恢复成功后应用重新加载，页面展示恢复后的数据。

## 七、验证记录

- 前端备份服务测试覆盖有效预览、损坏文件、格式版本、缺失字段、错误数值类型、孤儿外键与自动安全备份调用。
- Rust 恢复模块测试覆盖有效格式、未来格式拒绝、孤儿外键拒绝、成功恢复以及唯一约束写入失败时的完整事务回滚。
- 当前限制：只要当前数据库存在 `files` 附件记录，恢复会拒绝执行；附件数据包恢复属于后续格式升级工作。
- 尚未完成真实桌面端的“选择文件 → 恢复 → 重启后核对”手动验收；应在 R0 发布冒烟阶段使用非生产数据完成一次验证。
