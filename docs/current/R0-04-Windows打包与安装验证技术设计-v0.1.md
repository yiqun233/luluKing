## 一、目标与边界

本任务建立可重复的 Windows 发布方式，并明确安装、升级和卸载过程中的数据保留规则。

本任务包含：

- 使用 Tauri 的 NSIS 目标生成 Windows 安装包。
- 固定安装器语言、安装范围、WebView2 安装方式和升级策略。
- 写明数据库、设置和备份的本地位置与卸载行为。
- 创建发布前检查、安装验证和升级验证清单。

本任务不包含：

- 代码签名证书采购和签名自动化。
- 自动更新服务器、增量更新和静默升级。
- 在本阶段收紧 CSP 或权限范围；该工作属于 R2.1。

## 二、发布配置

### 2.1 安装器选择

当前使用 NSIS 而非 MSI：开发环境未安装 WiX，NSIS 由 Tauri 在项目 `src-tauri/target/.tauri/` 缓存，便于离线复用和降低机器环境差异。

安装器配置：

- 安装范围：当前用户，不请求管理员权限。
- 安装语言：简体中文。
- 升级策略：禁止降级安装。
- WebView2：首次安装时静默下载引导程序，因此首次安装需要网络。
- 开始菜单：创建 `luluKing` 文件夹和应用快捷方式。

### 2.2 数据位置与卸载策略

`tauri-plugin-sql` 将 `sqlite:app.db` 解析到应用配置目录；Windows 默认位置为：

```text
%APPDATA%\com.yi.luluKing\app.db
```

AI 设置文件保存在同一应用数据根目录；JSON 备份保存在 `%APPDATA%\com.yi.luluKing\luluKing\backups\`。安装程序仅管理程序文件；卸载应用不会主动删除 `%APPDATA%\com.yi.luluKing\`，以保留用户数据和安全备份。

如需彻底移除数据，用户应先在设置页创建备份，再手动删除上述目录。此操作不可恢复。

## 三、构建与发布步骤

1. 确认 `src-tauri/tauri.conf.json` 的版本、标识符与安装器配置。
2. 运行前端构建、全量测试与 Rust 检查。
3. 运行 `npm run release:windows`。
4. 从 `src-tauri/target/release/bundle/nsis/` 获取安装程序。
5. 记录安装包文件名、版本、大小和 SHA-256。
6. 在干净 Windows 用户环境完成下方手动清单；通过后才可发布。

## 五、手动验收清单

### 4.1 首次安装

- [ ] 使用未安装过 luluKing 的 Windows 用户运行安装包。
- [ ] 确认安装器为简体中文，且不要求管理员权限。
- [ ] 联网环境下确认 WebView2 缺失时可正常安装。
- [ ] 从开始菜单启动应用，窗口和基础页面正常显示。
- [ ] 新建一条任务、一个项目和一条笔记，重启后数据仍存在。

### 4.2 卸载与数据保留

- [ ] 在设置页创建一份备份，并记录最近备份时间。
- [ ] 卸载应用后确认程序快捷方式消失。
- [ ] 确认 `%APPDATA%\com.yi.luluKing\app.db` 和备份仍然存在。
- [ ] 重新安装同版本后确认之前创建的数据仍可读取。

### 4.3 升级安装

- [ ] 用旧版本创建包含任务、标签和笔记链接的数据，并创建备份。
- [ ] 安装新版本，不先卸载旧版本。
- [ ] 启动后确认数据库迁移完成、旧数据可查询和编辑。
- [ ] 验证设置页备份预览和恢复入口可用。
- [ ] 确认无法安装比当前版本更低的安装包。
