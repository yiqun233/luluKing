## 一、技术栈选型

### 1.1 选型总览

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2.0** | 轻量（~5MB）、内存占用小、tauri-plugin-sql 原生 SQLite、未来可扩移动端 |
| 前端 | **React 18 + TypeScript** | 复杂交互、类型安全、生态成熟 |
| UI 组件 | **shadcn/ui + Tailwind CSS** | 可定制不锁定、卡片式布局友好 |
| 状态管理 | **Zustand**（UI 态）+ **TanStack Query**（数据态） | 轻量灵活 + 数据缓存失效 |
| 数据库 | **SQLite**（tauri-plugin-sql） | 嵌入式零依赖、结构化关联、FTS5 全文搜索、本地单文件 |
| 数据访问 | **Repository 模式**（TS 封装 SQL） | 前端直接执行 SQL，几乎不写 Rust |
| 富文本 | **Tiptap**（ProseMirror） | 知识库/复盘编辑、自定义双链节点 |
| 拖拽 | **dnd-kit** | 周计划双栏拖拽、日历拖动 |
| 日期 | **date-fns** | 轻量 tree-shakeable |
| 全文搜索 | **SQLite FTS5** | 原生支持，零额外依赖 |
| AI 调用 | **tauri-plugin-http** + **tauri-plugin-store** | 绕过 CORS 调用云端 API + Key 安全存储 |
| 构建 | **Vite** | Tauri 默认、HMR 快 |

### 1.2 为什么选 Tauri 而非 Electron

| | Tauri 2.0 | Electron |
|---|---|---|
| 安装包体积 | ~5MB | ~100MB+ |
| 内存占用 | 低 | 高（~200MB+） |
| 后端语言 | Rust | Node.js |
| SQLite 支持 | tauri-plugin-sql 原生 | better-sqlite3 |
| 移动端扩展 | 2.0 支持 | 不支持 |
| Rust 代码量 | 极少（仅插件配置） | 无 |

选择 Tauri：个人工作台是长期常驻应用，轻量很重要。通过 tauri-plugin-sql，数据访问全在 TypeScript，Rust 端仅几行插件配置。

### 1.3 为什么选 SQLite 而非 MySQL/PostgreSQL

SQLite 是**嵌入式数据库**，库内嵌进应用、无服务进程、打开即用。MySQL/PostgreSQL 是**服务端数据库**，需单独运行数据库服务。

个人桌面应用选 SQLite 的理由：
- 打开即用，不依赖后台服务
- 数据库就是一个 .db 文件，备份即复制
- 数据量（几千条）性能无压力
- Notion、Obsidian、Logseq 等同类工具均用嵌入式数据库

多端同步的正确方案是 **Local-First（本地 SQLite + 同步层）**，而非直连远程数据库（离线不可用）。同步后置到 P5 阶段。

### 2.2 应用形态

- **纯本地一体化应用**，打包成一个 `.exe`，双击即用
- **无独立后端服务**，应用内分层（UI 层 / 数据层 / 系统层）在同一进程
- **离线可用**，所有数据在本地 SQLite
- **联网时**可调用云端 AI API（不依赖网络可用性）

### 2.3 分层职责

| 层 | 职责 | 技术 |
|---|---|---|
| UI 层 | 页面渲染、用户交互 | React + shadcn/ui |
| 状态层 | UI 状态、数据缓存 | Zustand + TanStack Query |
| AI 调用层 | 调用云端 AI API、流式响应、Key 管理 | aiClient.ts + tauri-plugin-http |
| Repository 层 | 数据访问、SQL 封装、类型映射 | TS 手写 SQL |
| 系统层 | 数据库引擎、文件系统、HTTP 通道 | Tauri Rust 插件 |
| 存储层 | 数据持久化、文件存储 | SQLite + 本地文件 |

## 三、数据模型设计

### 3.1 设计原则

- **同步预留**：所有数据表含 `created_at`、`updated_at`、`deleted_at`、`synced_at`，为 P5 多端同步预留
- **软删除**：用 `deleted_at` 标记删除，不物理删除（同步需要知道"删除"也是变更）
- **多态标签**：一张 `taggables` 表服务所有实体类型
- **收件箱/知识库同表**：`notes` 表用 `status` 字段区分（inbox/knowledge）
- **全文搜索**：FTS5 虚拟表索引笔记标题+正文

### 3.2 完整 Schema

```sql
-- ============================================================
-- 执行层
-- ============================================================

-- 任务
CREATE TABLE tasks (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'todo',  -- todo/done/abandoned
  plan_date   TEXT,                          -- 计划日期（我打算哪天做）
  due_date    TEXT,                          -- 截止日期（最晚何时做完）
  is_key      INTEGER NOT NULL DEFAULT 0,    -- 重点标记（二元）
  project_id  INTEGER REFERENCES projects(id) ON DELETE SET NULL,
  notes       TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- 清单项（挂在任务下，纯勾选）
CREATE TABLE checklist_items (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id     INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  title       TEXT NOT NULL,
  done        INTEGER NOT NULL DEFAULT 0,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- 日程事件
CREATE TABLE events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,
  type        TEXT NOT NULL,                 -- task_block/independent
  date        TEXT NOT NULL,                 -- 日期
  start_time  TEXT,                          -- 开始时间（空=全天）
  end_time    TEXT,                          -- 结束时间
  task_id     INTEGER REFERENCES tasks(id) ON DELETE SET NULL,  -- 空=独立事件
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- ============================================================
-- 组织 / 方向层
-- ============================================================

-- 项目
CREATE TABLE projects (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  title             TEXT NOT NULL,
  type              TEXT NOT NULL DEFAULT 'delivery',  -- delivery/study
  status            TEXT NOT NULL DEFAULT 'inactive',  -- inactive/active/done/archived/abandoned
  is_focus          INTEGER NOT NULL DEFAULT 0,        -- 是否当前聚焦
  progress_override INTEGER,                           -- 手动覆盖进度（空=自动算）
  goal_id           INTEGER REFERENCES goals(id) ON DELETE SET NULL,
  notes             TEXT,
  created_at        TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at        TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at        TEXT,
  synced_at         TEXT
);

-- 项目素材（学习研究型项目的书/文章/视频）
CREATE TABLE materials (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id  INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,                -- book/article/video/doc
  title       TEXT NOT NULL,
  author      TEXT,
  pages       INTEGER,
  progress    INTEGER NOT NULL DEFAULT 0,   -- 进度百分比或页数
  notes       TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- 目标
CREATE TABLE goals (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  title            TEXT NOT NULL,
  period_type      TEXT NOT NULL,            -- quarter/year/long
  period_value     TEXT,                     -- 如 "2026-Q3" / "2026" / "long"
  progress_type    TEXT NOT NULL,            -- count/aggregate
  progress_target  INTEGER,                  -- 计数型目标值
  progress_current INTEGER NOT NULL DEFAULT 0,
  status           TEXT NOT NULL DEFAULT 'active',  -- active/done/abandoned
  notes            TEXT,
  created_at       TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at       TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at       TEXT,
  synced_at        TEXT
);

-- ============================================================
-- 例行层
-- ============================================================

-- 习惯
CREATE TABLE habits (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  title            TEXT NOT NULL,
  frequency_type   TEXT NOT NULL,            -- daily/weekly
  frequency_target INTEGER NOT NULL DEFAULT 1,  -- 每周次数（weekly型用）
  goal_id          INTEGER REFERENCES goals(id) ON DELETE SET NULL,
  status           TEXT NOT NULL DEFAULT 'active',  -- active/paused/archived
  pause_until      TEXT,
  best_streak      INTEGER NOT NULL DEFAULT 0,
  created_at       TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at       TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at       TEXT,
  synced_at        TEXT
);

-- 习惯打卡记录（一天一条 = 打卡）
CREATE TABLE habit_logs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  habit_id    INTEGER NOT NULL REFERENCES habits(id) ON DELETE CASCADE,
  date        TEXT NOT NULL,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  synced_at   TEXT,
  UNIQUE(habit_id, date)
);

-- ============================================================
-- 沉淀层
-- ============================================================

-- 主题（知识库粗骨架，5~8个）
CREATE TABLE subjects (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- 笔记 / 知识条目（收件箱 + 知识库同表）
CREATE TABLE notes (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  title               TEXT,                          -- inbox可空，knowledge必填
  content             TEXT NOT NULL DEFAULT '',
  status              TEXT NOT NULL DEFAULT 'inbox', -- inbox/knowledge
  subject_id          INTEGER REFERENCES subjects(id) ON DELETE SET NULL,  -- knowledge必填
  source              TEXT NOT NULL DEFAULT 'inbox', -- inbox/new/review/study
  related_goal_id     INTEGER REFERENCES goals(id) ON DELETE SET NULL,
  related_project_id  INTEGER REFERENCES projects(id) ON DELETE SET NULL,
  created_at          TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at          TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at          TEXT,
  synced_at           TEXT
);

-- 双向链接（笔记 <-> 笔记/实体）
CREATE TABLE note_links (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  source_note_id  INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  target_note_id  INTEGER REFERENCES notes(id) ON DELETE CASCADE,  -- 空=链向非笔记实体
  target_type     TEXT,    -- note/goal/project/task
  target_id       INTEGER,
  link_text       TEXT NOT NULL,
  created_at      TEXT NOT NULL DEFAULT (datetime('now')),
  synced_at       TEXT
);

-- ============================================================
-- 横切层
-- ============================================================

-- 标签
CREATE TABLE tags (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL UNIQUE,
  color       TEXT,
  status      TEXT NOT NULL DEFAULT 'active',  -- active/archived
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at  TEXT,
  synced_at   TEXT
);

-- 标签多态关联（一张表服务所有实体）
CREATE TABLE taggables (
  tag_id        INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  taggable_type TEXT NOT NULL,    -- task/project/goal/note/habit/event/review
  taggable_id   INTEGER NOT NULL,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  synced_at     TEXT,
  PRIMARY KEY (tag_id, taggable_type, taggable_id)
);

-- 复盘
CREATE TABLE reviews (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  type          TEXT NOT NULL,              -- week/month
  period_start  TEXT NOT NULL,
  period_end    TEXT NOT NULL,
  auto_summary  TEXT,                       -- 自动摘要（JSON）
  content       TEXT,                       -- 手动内容（引导问题回答等）
  status        TEXT NOT NULL DEFAULT 'draft',  -- draft/done/skipped
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at    TEXT,
  synced_at     TEXT
);

-- 周期计划
CREATE TABLE plans (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  type          TEXT NOT NULL,              -- week/month
  period_start  TEXT NOT NULL,
  period_end    TEXT NOT NULL,
  content       TEXT,                       -- 计划内容（JSON）
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at    TEXT,
  synced_at     TEXT
);

-- ============================================================
-- 文件存储
-- ============================================================

-- 文件元信息（图片、附件等）
CREATE TABLE files (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  filename      TEXT NOT NULL,              -- 存储文件名（含扩展名）
  original_name TEXT,                       -- 原始文件名
  mime_type     TEXT,
  size          INTEGER,
  path          TEXT NOT NULL,              -- 相对路径（files/xxx）
  -- 可关联到笔记（笔记内图片/附件）
  note_id       INTEGER REFERENCES notes(id) ON DELETE SET NULL,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  synced_at     TEXT
);

-- ============================================================
-- 全文搜索
-- ============================================================

-- FTS5 虚拟表，索引笔记标题+正文
CREATE VIRTUAL TABLE notes_fts USING fts5(
  title,
  content,
  content=notes,
  content_rowid=id,
  tokenize='unicode61'    -- 支持中文分词（按字分词）
);

-- 触发器：笔记变更时同步 FTS 索引
CREATE TRIGGER notes_ai AFTER INSERT ON notes BEGIN
  INSERT INTO notes_fts(rowid, title, content) VALUES (new.id, new.title, new.content);
END;
CREATE TRIGGER notes_ad AFTER DELETE ON notes BEGIN
  INSERT INTO notes_fts(notes_fts, rowid, title, content) VALUES('delete', old.id, old.title, old.content);
END;
CREATE TRIGGER notes_au AFTER UPDATE ON notes BEGIN
  INSERT INTO notes_fts(notes_fts, rowid, title, content) VALUES('delete', old.id, old.title, old.content);
  INSERT INTO notes_fts(rowid, title, content) VALUES (new.id, new.title, new.content);
END;

-- ============================================================
-- 同步元数据（P5 用，现在建表预留）
-- ============================================================

CREATE TABLE sync_state (
  id              INTEGER PRIMARY KEY,
  device_id       TEXT NOT NULL,
  last_sync_at    TEXT,
  created_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

-- ============================================================
-- 索引
-- ============================================================

CREATE INDEX idx_tasks_plan_date ON tasks(plan_date) WHERE deleted_at IS NULL;
CREATE INDEX idx_tasks_status ON tasks(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_tasks_project ON tasks(project_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_events_date ON events(date) WHERE deleted_at IS NULL;
CREATE INDEX idx_habit_logs_date ON habit_logs(habit_id, date);
CREATE INDEX idx_notes_status ON notes(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_notes_subject ON notes(subject_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_note_links_source ON note_links(source_note_id);
CREATE INDEX idx_note_links_target ON note_links(target_note_id);
CREATE INDEX idx_taggables_lookup ON taggables(taggable_type, taggable_id);
CREATE INDEX idx_projects_focus ON projects(is_focus) WHERE deleted_at IS NULL;
```

```

reviews (独立，auto_summary + content)

```

// repositories/taskRepo.ts
import { getDb } from '../db/client'
import type { Task } from '../types/entities'

export const taskRepo = {
  async getByPlanDate(date: string): Promise<Task[]> {
    const db = await getDb()
    return db.select<Task[]>(
      `SELECT * FROM tasks
       WHERE plan_date = ? AND status = ? AND deleted_at IS NULL
       ORDER BY is_key DESC, created_at`,
      [date, 'todo']
    )
  },

  async create(data: Partial<Task>): Promise<number> {
    const db = await getDb()
    const result = await db.execute(
      `INSERT INTO tasks (title, plan_date, due_date, is_key, project_id)
       VALUES (?, ?, ?, ?, ?)`,
      [data.title, data.plan_date, data.due_date, data.is_key ? 1 : 0, data.project_id]
    )
    return result.lastInsertId
  },

  async updateStatus(id: number, status: string): Promise<void> {
    const db = await getDb()
    await db.execute(
      `UPDATE tasks SET status = ?, updated_at = datetime('now') WHERE id = ?`,
      [status, id]
    )
  },
}

## 八、版本升级与数据迁移

### 8.1 问题背景

本地桌面应用的数据在用户本地，每次更新应用可能改了数据库 schema。"旧数据 + 新程序"时，必须在启动时自动升级数据库结构，否则数据损坏。

两件事分开：
- **应用更新**：替换 .exe（手动替换 or tauri-plugin-updater 自动更新）
- **数据迁移**：新应用启动时，自动把旧数据库 schema 升级到新版

### 8.2 版本化迁移机制

数据库存一张元数据表记录当前版本：

```sql
CREATE TABLE schema_migrations (
  version    INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

每次改 schema 写一个带版本号的迁移脚本：

```
src/db/migrations/
├── 001_initial.sql          # P0 初始建表
├── 002_add_ai_logs.sql      # 加 AI 日志表
├── 003_add_note_excerpt.sql # 加字段
└── ...
```

应用启动时自动执行（见 5.1 节 migrator 逻辑）：

```ts
async function runMigrations() {
  const db = await getDb()
  const current = await db.select<{version: number}[]>(
    'SELECT MAX(version) as version FROM schema_migrations'
  )
  const currentVersion = current[0]?.version ?? 0
  const pending = migrations.filter(m => m.version > currentVersion)

  if (pending.length > 0) {
    await backupDatabase('app.db.pre-migration.bak')  // 迁移前备份
  }

  for (const m of pending) {
    await db.execute('BEGIN TRANSACTION')
    try {
      await db.execute(m.sql)
      await db.execute(
        'INSERT INTO schema_migrations (version) VALUES (?)', [m.version]
      )
      await db.execute('COMMIT')
    } catch (e) {
      await db.execute('ROLLBACK')
      throw e
    }
  }
}
```

### 8.3 跨版本链式升级

用户可能从旧版直接升到最新（v1 -> v5）。迁移链式执行：依次跑 002 -> 003 -> 004 -> 005。每个迁移是"上一版到这一版"的增量，按顺序跑即可从任意旧版升到最新。

### 8.4 迁移安全三道防线

| 防线 | 机制 |
|---|---|
| 事务 | 每个迁移在单个 SQLite 事务内，失败 ROLLBACK，不留中间态 |
| 迁移前备份 | 执行前复制 app.db，极端情况可恢复 |
| 启动校验 | 迁移失败 -> 恢复备份 -> 报错提示，绝不带损坏数据继续跑 |

### 8.5 迁移脚本原则

- 只做增量变更（ALTER TABLE ADD COLUMN 等），不重写全表
- SQLite 改字段类型/删字段能力有限，复杂变更用"建新表 -> 复制数据 -> 删旧表 -> 改名"
- 改了字段要同步填充已有数据（UPDATE）
- **每个迁移发布前，必须拿真实数据测一遍**，不能只在空库上测

### 8.6 数据可移植：导出 / 导入

| 需求 | 方案 |
|---|---|
| 换电脑 | 导出 app.db + files/ 为 .zip，新机器导入 |
| 手动备份 | 一键导出，心里踏实 |
| 不被锁定 | 数据是用户的，软件停更也能导出 |

### 8.7 开发期数据管理

```
开发环境：app.dev.db    （测试数据，随便折腾）
生产环境：app.db        （真实数据，谨慎迁移）
```

开发时用 dev 库随便改 schema，发布前用真实数据验证迁移脚本。

### 8.8 更新流程全图

```
用户更新应用（手动替换 or 自动更新）
         │
         ▼
    新版 .exe 启动
         │
         ▼
    检查数据库版本
         │
    版本一致？──是──▶ 正常启动
         │
         否
         │
         ▼
    备份数据库
         │
         ▼
    链式执行迁移（每个在事务内）
         │
    全部成功？──是──▶ 正常启动
         │
         否
         │
         ▼
    恢复备份，报错提示
```
